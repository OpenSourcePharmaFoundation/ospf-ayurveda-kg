## Decision point: start GNN with current data or fill the graph first?

The GNN can only learn from what's in the graph. Right now, ChemBL secondary
data (mechanisms, indications, targets) is test-only — 10 mechanism records when
there should be ~2,500. The `bridging-the-gap.md` doc flags this as the #1 gap.

**Option A — Start GNN on current data.** The graph has ~3,276 drugs, DisGeNET
gene-disease associations, IMPPAT plant-compound data, and PubChem target
interactions. That's enough to build the export script and get a training loop
running. The GNN won't perform well, but the pipeline will exist, and full data
can be swapped in later.

**Option B — Run full ChemBL collection first.** Takes 8-12 hours of compute
(automated scraping, not dev time). The GNN trains on a much richer graph. But
this delays writing any GNN code by a day or two while data collects.

**Recommended: A, with B running in parallel.** Start the full ChemBL scrape
on day 1 and let it run in the background. Meanwhile, write the Neo4j export
script against the current data. By midweek, the full data will be ready and the
export script will be done — swap in the full data and proceed to GNN training.

### Day 2 (Tuesday) — Neo4j export script (Phase 1)

Write `src/gnn/export_graph.py` — connects to Neo4j, exports the heterogeneous
graph into a PyG `HeteroData` object. Concrete subtasks:

- [ ] Export all node types with their properties as feature tensors
  - Drug: molecular_weight, alogp, hba, hbd, psa, rtb, ro5_violations,
    aromatic_rings, heavy_atoms, qed_weighted (10 numeric features)
  - Gene: gdaScore (from edges — aggregate per gene)
  - Compound, Protein, Plant, Formulation, Disease, Therapeutic_Area: learnable
    embeddings (no numeric features — just IDs)

- [ ] Export all edge types as edge index pairs
  - Map each relationship type to a (src_type, rel_type, dst_type) tuple
  - TARGETS, TREATS, PRODUCES, CONTAINS, ASSOCIATED_WITH, TRANSLATION, etc.

- [ ] Build node ID → integer index mappings for each type

- [ ] Save the HeteroData object as a `.pt` file in `data/processed/`

- [ ] Validate: load the saved file, print node counts and edge counts per type,
  confirm they match Neo4j query results

### Day 3 (Wednesday) — Verify ChemBL data + re-import

### Day 4 (Thursday) — GNN training loop (Phase 2 start)

Write `src/gnn/train_link_prediction.py` — the core training pipeline:

- [ ] Define the R-GCN model using PyG's `to_hetero()` on a base GCN
  - 2 message-passing layers, 128-dim hidden, ReLU activation
  - This is the architecture the glossary describes

- [ ] Implement train/val/test split on TARGETS edges (80/10/10)
  - Use PyG's `RandomLinkSplit` transform for heterogeneous graphs

- [ ] Implement negative sampling
  - For each real TARGETS edge, sample 1 fake edge (same source type, random
    target) as a negative example

- [ ] Training loop with binary cross-entropy loss
  - Adam optimizer, lr=0.01
  - Train for 100 epochs, log validation AUC-ROC every 10 epochs

- [ ] Save trained model + training curves

### Day 5 (Friday) — Evaluate + baselines (Phase 2/3)

- [ ] Evaluate on test set: AUC-ROC, MRR, Hits@10
  - These are all defined in the glossary — this is where they become real

- [ ] Implement baselines for comparison
  - Random predictor (floor)
  - Shortest-path heuristic (BFS distance between node pairs)

- [ ] Print a comparison table: GNN vs. random vs. shortest-path

- [ ] If time: run batch prediction on all missing TARGETS edges
